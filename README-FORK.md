# ComfyUI-H3-VisionPromptor-Planner — форк с выходами под LongMedia Planner

Форк [benjiyaya/ComfyUI-H3-VisionPromptor](https://github.com/benjiyaya/ComfyUI-H3-VisionPromptor) v1.0.0.
Версия форка: **1.1.0**.

Нода `H3VisionPromptor` получает второй режим — **Planner mode** — и продолжает
работать как локальный (без API-ключей) генератор промптов MiniMax H3 на
нативном VLM-стеке ComfyUI. Режимы переключаются одним тумблером и
взаимоисключимы.

## Назначение

Готовить MultiClip-раскадровки для
[vizart-vj/ComfyUI-MiniMax-H3-LongMedia](https://github.com/vizart-vj/ComfyUI-MiniMax-H3-LongMedia):
текст клипов для **LongMedia Planner** и карточки камер для **LongMedia
Cameras**. Ни Planner, ни Cameras не форкаются и не дорабатываются — форк
только выдаёт совместимые тексты/JSON.

## Быстрый старт

1. Установите форк в `ComfyUI/custom_nodes/` **вместо** оригинального
   ComfyUI-H3-VisionPromptor (node_id совпадает — `H3VisionPromptor`;
   параллельная установка оригинала и форка в одну ComfyUI конфликтует).
   Перезапустите ComfyUI.
2. Поставьте ComfyUI-MiniMax-H3-LongMedia (для приёма выходов).
3. Откройте `example_workflows/h3_vision_promptor_planner.json`, выберите свой
   VLM в CLIPLoader, впишите идею, включите `emit_planner_outputs`.
4. Соедините: `planner_prompt` → вход `multiclip_prompt` Planner'а,
   `global_prompt` → вход `global_prompt` Planner'а. Включите у Planner'а
   *Auto Import* (или нажмите *Import*) — тексты клипов разъедутся по
   карточкам.
5. `clip_durations` и `camera_params` — контрольные значения: длительности
   выставьте в карточках Planner'а вручную (текстовый импорт длительности
   Planner игнорирует), карточки камер перенесите в Cameras вручную (у Cameras
   пока нет текстового импорта — JSON подготовлен так, чтобы при появлении
   такого входа его можно было подать как есть).

## Управление режимами

| | `emit_planner_outputs = false` | `emit_planner_outputs = true` |
|---|---|---|
| Активные выходы | `prompt`, `vision_context` | `planner_prompt`, `planner_prompt_ru`, `global_prompt`, `clip_durations`, `camera_params`, `reference_images_status` |
| Неактивные выходы | 6 planner-сокетов скрыты (JS) и возвращают `""` | `prompt`/`vision_context` затемнены (JS) и возвращают `""` |
| `debug` | живой (как в оригинале) | живой (JSON плана, бюджеты токенов, warnings) |
| Поведение | байт-в-байт оригинал (проверено тестом против исходного пакета) | vision-проход → planner-проход → перевод → сборка выходов |

Техническое ограничение UI: ComfyUI адресует выходы **по индексу слота**,
поэтому «физически» удаляются только хвостовые planner-сокеты (режим false);
головные сокеты `prompt`/`vision_context` в planner-режиме остаются на месте,
но визуально погашены и всегда пусты. Значения выходов переключаются на
сервере в любом случае — «случайно подключить не то» невозможно.

## Входы (изменения относительно оригинала)

- **`emit_planner_outputs`** (BOOLEAN, default false) — переключатель режима.
- **`total_duration`** (FLOAT, 8–2400 с, default 24.0) — общая длительность
  ролика в planner-режиме.
- **`duration`** (4–15 с) — в planner-режиме трактуется как **целевая длина
  одного клипа**. `clip_count = ceil(total / target)`, clamp 2–16 клипов
  (лимиты LongMedia), каждый клип ≤ 150 с; распределение — равномерное,
  округлительный остаток в последний клип. Длительности считаются
  арифметикой, а не VLM.
- `variants` в planner-режиме форсируется в 1 (варианты сломали бы формат
  импорта) — в debug пишется предупреждение.
- Бюджет токенов planner-прохода форк считает сам (клипы + глобал + JSON
  камер), независимо от виджета `max_tokens` (clamp 2048..8192; фактические
  значения — в debug).
- Остальные входы без изменений. Vision-проход по референсам работает как в
  оригинале; `<Picture k>`-метки вплетаются в тексты клипов.

## Выходы planner-режима

1. **`planner_prompt`** — секции `clip_1:` … `clip_N:` (2–16), по одной
   на клип, **без камерной лексики** (ею владеет Cameras; в клипах — только
   сцена/действие/континуити). Диалоги `<d>[Russian] … </d>` разрешены и
   проходят нетронутыми. Формат гарантированно импортируется парсером
   Planner'а: (а) форк испускает только «голые» метки `clip_N:`; (б) строки
   тела, начинающиеся с `Clip N …`, автоматически нейтрализуются (иначе парсер
   LongMedia принял бы их за новые заголовки и тихо испортил импорт); (в)
   кросс-проверка парсером-двойником включена в тесты.
2. **`planner_prompt_ru`** — русское зеркало того же плана: `GLOBAL:` +
   `clip_N:` (второй проход перевода; метки, `<d>`-диалоги и `<Picture N>`
   сохраняются байт-в-байт; температура перевода понижена до 0.3). Глобал
   живёт внутри RU-выхода — отдельного седьмого выхода нет.
3. **`global_prompt`** — константа сцены для одноимённого входа Planner'а
   (импортёр `multiclip_prompt` преамбулу отбрасывает, поэтому глобал —
   отдельный провод).
4. **`clip_durations`** — JSON-массив длительностей каждого клипа
   (`[8.0, 8.0, 8.0]`). Чек-лист для карточек и задел на будущий умный импорт.
   Если модель выдала другое число клипов, чем план, — длительности
   пересчитываются по фактическому числу (сумма = total), см. debug.
5. **`camera_params`** — JSON-массив карточек **строго по 13 ключам карточки
   LongMedia Cameras**: `clip_id, clip_name, shot_size, rig, camera_body,
   lens, stabilization, movement, speed, transition_type, space_relation,
   entity_continuity, transition_to_next` (последнему клипу `false`).
   Значения — только из словаря Cameras (13 shot size, 25 rig, 29 body, 32
   lens, 10 stabilization, 35 movement, 8 speed, 4 transition, 3 space, 3
   entity ≈ 160 значений с семантическими описаниями, скопированными из
   серверных словарей LongMedia v0.6.40). Знания инъектируются в системный
   промпт генератора; невалидное значение форк нормализует (fuzzy) или
   заменяет дефолтом с предупреждением в debug. Словарь автономно лежит в
   `py/camera_knowledge.py` — LongMedia не импортируется; при изменении его
   словаря файл нужно зеркально обновить.
6. **`reference_images_status`** — `{"images_connected": true, "count": 2,
   "slots": ["image_0","image_1"]}` (или `false/0/[]`). IMAGE-тензоры путей не
   несут, поэтому выход — маркер наличия/количества, а не пути. Поданные на
   генерацию картинки пользователь подаёт и на генерацию видео.

## Как работает генерация

Один planner-проход с жёстким контрактом секций:

```
=== GLOBAL ===
<константа сцены, 40–70 слов>

=== CLIPS ===
clip_1: … clip_N:            (по 50–90 слов, без камер)

=== CAMERAS ===
[{…}, {…}, {…}]              (JSON, N карточек)
```

Форк расщепляет ответ детерминированно; фоллбеки с предупреждениями: нет
GLOBAL → `global_prompt=""` (клипы остаются самодостаточными); нет CAMERAS →
`"[]"`; нет `clip_N:` → все planner-выходы пустые + ошибка в debug. Штатный
`post_processor.finalize()` в planner-режиме полностью обходится — его
sanitize по H3-заголовкам и авто-дописывание `overall_soundscape: N/A`
исказили бы мультиклип-текст. Вместо него — лёгкий клинер (снятие
code-fences и think-блоков, ничего не добавляет и не отрезает).

Системные промпты: `prompts/planner_system.txt` (контракт + полный словарь
камер через плейсхолдер `{{CAMERA_KNOWLEDGE_BLOCK}}`) и
`prompts/planner_translate.txt`. Оба хотрелоадятся с диска; правьте без
перезапуска. `custom_system_prompt` в planner-режиме по-прежнему заменяет
встроенный системный промпт целиком (тогда словарь камер не инъектируется).

## Известные ограничения

- Камеры: перенос карточек в ноду Cameras — руками (текстового входа у Cameras
  нет; JSON готов к будущему импорту).
- Длительности: карточный импорт Planner'а игнорирует длительности из текста —
  выставляйте по `clip_durations`.
- RU-зеркало не проходит дефузинг строк-«псевдозаголовков» (для русского текста
  грамматика `clip/shot+N` практически не встречается); канал импорта — EN
  `planner_prompt`.
- Параллельная установка оригинала и форка в одну ComfyUI не поддерживается
  (одинаковый node_id `H3VisionPromptor`) — это цена drop-in совместимости
  старых воркфлоу.
